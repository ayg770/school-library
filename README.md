# School Library

מערכת ניהול ספריית בית ספר. עברית, RTL, offline-first.

## הרצה

```bash
npm install

npm run dev:server   # השירות המקומי — http://127.0.0.1:3000
npm run dev:ui       # הממשק        — http://127.0.0.1:5173
```

שני הטרמינלים במקביל. הממשק מפנה קריאות `/api` לשירות, כך שאין צורך בהגדרות
נוספות.

בדיקות ואיכות:

```bash
npm test        # בדיקות אוטומטיות
npm run typecheck
npm run lint
```

הנתונים נשמרים **מחוץ** לתיקיית הקוד — הנתיב המדויק מוצג במסך ההגדרות והתמיכה.
אפשר לעקוף אותו עם `LIBRARY_DATA_DIR`.

## מבנה

| חבילה | תפקיד |
|---|---|
| `packages/core` | דומיין, SQLite, מיגרציות, לוגים, הגדרות |
| `packages/server` | שירות HTTP מקומי, `/api/v1` |
| `packages/ui` | React, עברית RTL |

הממשק לא ניגש למסד הנתונים — רק דרך ה-API. הסיבה, ולמה קליפת האפליקציה עדיין
לא נבנתה, מתועדות ב-[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## שלבים

| | שלב | סטטוס |
|---|---|---|
| 0 | תשתית: DB, מיגרציות, שירות, מעטפת RTL | ✅ |
| 1 | קטלוג: כיתות, תלמידים, ספרים, עותקים | ✅ |
| 2 | השאלה והחזרה | ✅ |
| 3 | חוויית סורק ברקוד | ⬜ |
| 4 | ייבוא מקובץ + קליטת ספרים | ✅ |
| 5 | גיבוי ועדכון בטוח | ✅ |
| 6 | דוחות וייצוא | ⬜ |
| 7 | גישה ברשת מקומית | ⬜ |
| 8 | תשתית אינטגרציה | ⬜ |
| 9 | מחבר למערכת התלמידים | ⬜ |

**שלבים 0–2 ו-5 הושלמו.** המערכת משאילה ומחזירה ספרים, ויש גיבוי ושחזור.

**אפשר להתחיל להכניס נתונים אמיתיים** — יש ייבוא מאקסל, יש גיבוי, ויש השאלה
והחזרה.

מה שעדיין חסר:

| מה | למה זה חשוב |
|---|---|
| העלאה לאונליין | צריך אחסון עם דיסק קבוע |
| מסך בדיקת סורק וקליטה מהמדף | כשיהיה סורק ביד |
| דוחות וייצוא | נוחות, לא חוסם |

## משתמשים והרשאות

בכניסה הראשונה המערכת מבקשת ליצור מנהל מערכת. אחריו אפשר להוסיף משתמשים
נוספים במסך **משתמשים**.

| הרשאה | מה מותר |
|---|---|
| צפייה בלבד | לראות הכול, בלי לשנות |
| ספרן | השאלה, החזרה, קטלוג וייבוא |
| מנהל מערכת | הכול, כולל משתמשים, גיבוי ושחזור |
